Project: UTEP Campus Route Finder
The application is a web-based pedestrian route finder for the UTEP campus. The planned stack is:
SvelteKit
TypeScript
MapLibre
OpenStreetMap-derived geographic data
The routing system will support three route modes:
Shortest Route — minimizes walking distance
Easy Route — considers distance plus walking difficulty such as elevation/slope and stairs
ADA Accessible Route — excludes inaccessible paths such as stairs and uses accessible paths/entrances where available
The system is divided into four major subsystems:
UI / Map
Application / Controller
Routing
Campus Data
The high-level system architecture is already defined in Sections 1 and 2 of the SDD. Please do not independently redesign Sections 1 or 2 while doing your subsystem work. If your detailed design reveals that a system-level decision needs to change, bring it up with the team first so we keep the SDD consistent.

Important shared architecture rules
MapLibre is responsible for map visualization, not route calculation.
Routing logic should not be implemented directly inside Svelte UI components.
Route calculation should operate on the internal CampusGraph.
Campus Data should describe facts about paths, such as distance, stairs, slope, or accessibility.
The Routing subsystem decides how those facts affect route selection.
Increment 1 should not be designed in a way that prevents Easy Route, ADA Route, elevation-aware routing, or 3D visualization later.
Major SDD classes/interfaces should correspond to meaningful TypeScript implementation entities.
Do not create unnecessary classes just to make more CRC cards.
